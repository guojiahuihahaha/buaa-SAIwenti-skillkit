# 发票字段读取

## 数电票 PDF 的文本结构

电子发票（普通发票）PDF 的文本层按固定版式排布：表头标签先集中出现（发票号码、开票日期、购买方信息、销售方信息、项目名称、规格型号、单位、数量、单价、金额、税率/征收率、税额、合计、价税合计大写、小写、备注、开票人），随后才是对应的值。

用 Python 的 PDF 文本抽取库（如 pypdf / PyMuPDF）取全文，再按下列锚点取值：

- 发票号码：紧跟「发票号码：」标签段之后的 20 位数字；全文里唯一的 20 位连续数字通常就是它。逐位抄，不省零。
- 开票日期：形如「2026年10月23日」。
- 购买方 / 销售方：购买方通常为单位名（本单位是固定抬头），销售方为开票公司名；两者后面各跟一个统一社会信用代码/纳税人识别号。
- 金额 / 税额 / 价税合计：项目行给出不含税「金额」与「税额」，「合计」下给出两者，随后「价税合计（大写）」给出中文大写，「（小写）」给出带 ¥ 的数字。

## 金额口径（最关键）

报销金额一律取「价税合计（小写）」。不要用项目行的不含税金额，也不要用结算表里的预算或实际花销数。

原因：结算表常按不含税金额记账。实例：一张公文包发票不含税 168.14、税额 21.86、价税合计 190.00，结算表却记 168.14；一张键盘发票价税合计 189.75，结算表记 190（整数）。以发票价税合计为准，差异进差异清单。

## 大写复核小写

中文大写金额用于复核小写数字，防止读图或抽文本时错位。例：¥842.89 对应「捌佰肆拾贰圆捌角玖分」。大小写不一致时标「待确认」，不自行选一个。

## 扫描件与图片发票

- JPG / 扫描件没有文本层，需要读图。重点看清「合计 / 价税合计（小写）」一栏，容易把不含税金额或税额误当成总额。
- 拿不准就裁剪该区域放大后再读；仍不确定标「待确认」，请用户给清晰版。
- 若同类物品先有 JPG 后补 PDF，以 PDF 文本为准重核，并把 JPG 归档或替换。

## 读后自检

- 每张发票的价税合计 = 金额 + 税额（允许四舍五入到分）。
- 发票号码为 20 位；位数不足多为漏零，回到原件逐位核。
- 购买方名称与税号应与本单位一致；税号位数明显少一位的，记入差异清单提示换开，只口头提示，不写进正式说明。
